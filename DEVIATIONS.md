# Deviations from the pre-registration

The pre-registration is [DESIGN.md](DESIGN.md), committed alone in the first commit of this repository
(SHA-256 `0d8805c2…08cd5c8`). Every change made during the sprint is logged here with its reason.
Changes are listed in the order they were made.

| # | Date | Section | Change | Reason |
|---|---|---|---|---|
| D1 | 2026-11-08 | §5.1 | Facts are dealt to all N positions with a seed that does not depend on `f`. Positions that become attackers lose their facts. Honest agents hold the same facts at every `f`. | In the original plan, facts were split over honest agents only, so each honest agent held more facts as `f` grew (about 4 at `f=0`, about 5.3 at `f=3/12`). That mixed up attacker fraction with information per agent. |
| D2 | 2026-11-08 | §5.1 | Redundancy `m` is `max(2, round(4N/24))` instead of a fixed 2. | With m=2, agents at N=200 would hold 0.24 facts each, so most ABM agents would be uninformed. This keeps about 4 facts per agent at every N. m=2 is unchanged at N=12. |
| D3 | 2026-11-08 | §8, §10.2 | Number of attackers k = nearest integer to `f·N`, halves rounded up. The effective `k/N` is logged and used in fits. | The ABM grid includes `f` values that are not multiples of 1/N. |
| D4 | 2026-11-08 | §8 | Random placement is nested: the attackers at `f=1/12` are a subset of those at `f=3/12` (same seed). | Makes the `f` comparison paired. |
| D5 | 2026-11-08 | §5.3, §6.1 | Rounds are indexed 0..R−1. Round 0 is an independent answer from private facts only; social updates happen in rounds 1..R−1. Onset `o` means the attacker behaves honestly in rounds `< o`. | The design left round 0 implicit. This keeps calls per run at N·R = 72 for the LLM, as budgeted. |
| D6 | 2026-11-08 | §13 | All ABM twins, modules and attacks live in `hiveguard/abm.py`. All LLM views and prompts live in `hiveguard/llm_strategies.py` and `hiveguard/agents.py`. There is no `strategies/` folder with one file per strategy. | Sprint time. The interfaces match §13 in spirit (`init/step` per strategy; modules as sender weights and gates). |
| D7 | 2026-11-08 | §5.5 | Sybil aliases (A4) multiply an attacker's weight only on board strategies (S4, S5, S9, S10) and in quorum counts on the board. With direct messages, A4 behaves like A2. | Aliases exist only on a shared medium. Direct messages carry the sender's real id. |
| D8 | 2026-11-08 | §10.3 | In the Stage B core block, strategies with no topology dependence (S0b, S1, S4, S7, S9) run on `full` only, not on both ring and full. S0a (oracle) runs once per seed at `f=0`. The core block is 84 runs (about 6k calls), not 126 runs (9k calls). | Only S2 and S3 read the graph. For the other strategies, ring and full runs are the same experiment with different sampling seeds. That spent about 3k calls on duplicates. The topology-free strategies cannot count toward H1, so H1's "≥5 of 7 strategies" threshold cannot be met. H1 is evaluated on S2 and S3 (LLM) and on S2, S3, S6 and S8 (ABM), and it is reported as the share of those strategies with a CI excluding 0. |
| D9 | 2026-11-08 | §6.2 | S0a and S0b use one round (N calls). S1 uses R independent rounds (N·R calls, compute-matched). | S0 has no dynamics, so extra rounds would only resample. |
| D10 | 2026-11-08 | §5.2 | An agent's confidence for A5 attackers is set to 1.0 by the environment after parsing. | Makes "maximizes self-reported confidence" independent of whether the model follows the instruction. Whether attacker models comply is logged separately (raw output). |
| D11 | 2026-11-08 | §7 | M1 (evaporation) on direct-message strategies down-weights a sender by (1−ρ)^streak, where streak is the number of consecutive rounds with an unchanged choice. M2 (stop signals) hides the whole sender (all its claims) for 2 rounds once any of its claims gets ≥2 distinct stoppers. | The design defined both modules on posts. These are the closest sender-level analogues, and the ABM and LLM forms are identical. |
| D12 | 2026-11-08 | §11, §12 | Analysis choices fixed before any calibrated or LLM data was seen. **ABM f-levels:** LLM fractions not on the ABM grid (e.g. 3/12) use the nearest effective f per N; ties are averaged per seed. **Duplicates:** Stage A rows are deduplicated on effective f (1/N and 0.05 coincide at N=12). **H0:** CI lower bound ≤ 0 at both f; outside Holm. **H1:** ≥5/7 share kept on the D8 strategy set. **H2:** "sharp" = f* inside the grid and 10–90% width ≤ 0.15; descriptive, no Holm. **H3:** value = contamination reduction / (max(0, accuracy loss) + 0.01); supported if M3 ranks first in ≥95% of resamples. **Compound H4/H7/H8:** max component p (intersection-union). **Holm:** separate ABM and LLM families. **Verdicts:** H5/H6 are capped at "inconclusive" with an uncalibrated ABM. **H6:** ρ over strategy×topology cells. **H8:** an unreached consensus counts as R. **H8/H9:** ranked over Tier-1 social strategies. **H10:** Hamming component distance; one-sided permutation Mantel test. | DESIGN left these operational details open. They are fixed in `hiveguard/analysis.py` and committed before calibration. |
| D13 | 2026-11-08 | §12.2 | The interactive results page and replay viewer are a static site deployed on Vercel, not the hosting named in §12.2. Content and features are unchanged. | Hosting choice by the author; a static site is portable and needs no account to view. |
| D14 | 2026-11-08 | §12.2, §13 | Two lines of DESIGN.md that named the original hosting platform for the results page were reworded to "a static web page" and "the results page", in the pre-registration commit itself. The SHA-256 above is of the edited file. No hypothesis, metric, threshold, grid or analysis choice changed. The edit was made after the code was written and before any calibrated or LLM result existed. | The hosting changed (D13), and the author wanted the pre-registration to stop naming that platform. Disclosed here because the pre-registration commit was rewritten. |
| D15 | 2026-11-08 | §5.3 | The output schema caps `claims` at 8 and `endorse`/`stop` at 3 each; the parser truncates longer lists. `max_tokens` is 1200. | In the pilot, the model endorsed every visible claim (60+ ids), which overran the token limit and made about 10% of replies invalid. Changed during the pilot, before any Stage B run. |
| D16 | 2026-11-08 | §5.3, §10.1 | LLM agents use the model's default reasoning ("thinking") mode, with `max_tokens` 8000. Only the final answer is parsed and logged. The pilot gains an S0a oracle check (all facts, f=0). Malformed individual claims are dropped instead of invalidating the reply. | In the pilot, `nemotron-3.5-lightning-30b-a3b` with thinking switched off solved the full-information task in only 53% of cases (12 seeds), so the benchmark would mostly measure arithmetic errors. With thinking on, it solved the hardest seeds. |
